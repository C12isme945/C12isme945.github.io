Overview

Restoring a ZIP backup is easy. Knowing whether the restoration is actually complete is harder. ArchiveLens creates a trusted SHA-256 manifest from your original archive, then compares a recovered copy file by file — showing exactly what changed, what is missing, and what appeared unexpectedly.

Everything runs locally in memory. There are no cloud accounts, no API keys, and no external requests. The only thing that persists is a report you deliberately download.

Highlights

01

Trusted manifests

Build a baseline from a known-good original, store it separately, and compare any later restoration against it.

02

Four honest verdicts

EXACT_MATCH, CHANGES_FOUND, REVIEW_EXTRAS or BLOCKED — no ambiguous “probably fine.”

03

Survives re-compression

Identical file content passes even when the ZIP container bytes differ, and the report records both facts.

04

Conservative safety limits

64 MiB compressed, 128 MiB expanded, 1,000 entries. Unsafe paths, links and corrupt members are blocked, not guessed at.

How it works

Original ZIP→ Manifest · SHA-256→ Recovered copy→ Inspectable report

Create the manifest once from the original archive, keep it independently, then verify any restored copy. A manifest generated from the same recovery copy proves nothing — the tool documents that limitation instead of hiding it.

Scope and limits

Archive formatsStored / deflated, unencrypted ZIP
Size limits64 MiB compressed · 128 MiB expanded · 32 MiB per member
ComparisonRelative paths + SHA-256 content hashes; empty files count
ExcludedDirectory entries, metadata, permissions, timestamps
Blocked inputLinks, path traversal, duplicates, Unicode collisions, extreme compression ratios
Not providedExtraction, deletion, malware scanning or manifest authentication
Honest by design. This proof of concept does not authenticate manifests, verify ongoing cloud availability, scan for malware, or guarantee that originals can safely be deleted. It has not had an independent security audit — the README says so directly.
